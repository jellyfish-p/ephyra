# PostgreSQL 保有任务权威，Streams 不决定重新评测

首版同时使用 PostgreSQL 与 Redis Streams，但任务及评测尝试状态以 PostgreSQL 为唯一真相；提交、任务和 Outbox 事件在同一数据库事务中落地，再向 Stream 可靠分发。Stream 重投或重复消费必须幂等核对既有状态，不能自动产生新的评测尝试，以免消息恢复语义绕过用户明确要求的“节点失联不自动重派，交由管理员处理”。

这优先保证任务可恢复与人工故障处置语义，而不是让队列消费状态替代业务状态。传输重连、重复通知和结果回报重传不等于重新执行选手程序；旧尝试的迟到结果也不能覆盖新尝试或新的评测数据版本。
