# OI / IOI：计分与反馈规则证据

> **仅供访谈决策，不是实现方案或已接受的架构决定。** 核查日期：2026-10-15（UTC）。只采用官方规则与官方赛事页面；不把某届规则称为普世“标准 OI”，也不要求 Ephyra 完全复刻某届赛事。ACM 不在本次研究范围。

## 2. 必须分清两层计分

**单次提交内部**：某提交在各测试点得分，如何合成为各子任务分，再合成该次总分。

**跨提交聚合**：多份提交中，哪些分数进入选手该题的最终成绩。这不是“有无实时反馈”的同义词。

设 `q[s,j]` 为提交 `s` 的子任务 `j` 得分（已按题面分值换算），则三种不同语义为：

- 最后一次：`Σj q[last,j]`。
- 整份提交最高：`max_s Σj q[s,j]`。
- 各子任务分别取历史最高：`Σj max_s q[s,j]`。

**IOI 官方库 2026 版与 IOI 2023 的明确事实**：[I26][I23] 的 *Tasks / Scoring* 均规定子任务各占一定分值；单次提交的子任务分默认取其测试点分的最小值，**但题面可以另定**；跨提交则逐子任务取最高，最后对子任务求和。原文关键句：

> “The final score for each subtask is the maximum of the scores for this subtask across all submissions.”

官方示例：两次提交的子任务分为 `(30,10)` 与 `(0,40)`，最终 **70**，不是整份提交最高的 **40**。这不能仅写成含混的“取最高分”。子任务允许题面定义部分分，不能一概推成“所有子任务只能全过或零分”。

版本差异也不能忽略：2023 文本在求和后保留两位小数；2026 文本先将各子任务分保留两位，再求和。[I23][I26]

## 3. IOI 反馈、期望输出和榜单不是一回事

| 问题 | 已核实的官方事实 |
| --- | --- |
| 赛中是否看分？ | 2026 与 2023 的 *Feedback* 都提供每次提交的各子任务分及简短编译报告；2023 *Appeal Process* 更明确写明临时成绩立即提供给选手。成绩仍可能因重测或申诉变化。[I26][I23] |
| 是否展示所有测试点结果？ | **不是。** 未满分子任务只反馈“最低得分测试点中序号最先的一个”，给编号及原因，例如正确、错误、部分正确、超时、执行失败；不能把它简化为“IOI 默认逐点完整反馈”。[I26][I23] |
| 是否要求公开隐藏测试的期望输出？ | **没有此要求。** 两版 *Feedback* 明确不提供实际测试数据、选手程序产生的输出及其他执行细节；2023 *Appeal Process* 明确评测数据赛中隐藏、赛后分析时开放。这里的“Output is correct”等是判定标签，不是期望输出文本。不得把样例、选手自测或赛后开放数据等同于赛中公开隐藏答案。[I26][I23] |
| 是否强制赛中实时榜？ | [R24] **E5.10.2**：“Provisional scores (including contestant names and countries) **may** be made available during the contest.” 是允许，而非必须；**S5.10** 要求的是赛事结束前产生完整最终成绩表。该条也不规定选手必须能访问公共榜单。实时个人分数不等于实时排名。 |

IOI 2023 官网确有 [Live Scoreboard 页面][B23]，现在指向赛后结果；它是该届存在此入口的证据，**不是所有 IOI 必须公开实时榜、或选手可在赛中看榜的证据**。2026 / 2023 的上述 Contest Rules 中也未找到强制实时榜条款。

## 4. NOI / NOIP：能证明什么，不能证明什么

- **NOI 历史规则**：[N07]“答案的提交”要求将答案保存为指定文件、放入指定目录；“评测和成绩发布”规定赛后 150 分钟内给领队成绩单，列出逐测试点得分及错误信息，并明确“每道题的得分为其在该题各个测试点上的得分之和”。这是该历史版本的**按点求和**，不是“所有 OI 必须采用加权子任务”的证明。
- **赛后答案开放**：[N07]“复测”规定，将复测所需的“测试数据和答案”在复测前下发；这有明确的**赛后阶段**，不能用来支持赛中显示期望输出。
- **NOIP 2024 修订组织流程**：[NP24] 第十一、十二、十六条规定收集源程序、竞赛结束后立即收取并由选手签字确认、上报主办方统一评测，初评发布后接受申诉。它说明赛后收卷/统一评测流程，**不是**“对在线提交历史执行最后一次 / 整份最高 / 子任务最高”的算法定义。
- 这些文件没有为现代在线系统完整规定赛中编译信息、样例测试、隐藏测试判定的可见性，也没有给出近年所有 NOI / NOIP 场次一致的跨提交规则。本次**未核实**可把“最后一次在线提交且场中完全不反馈通过/失败”作为跨赛事统一标准的官方依据；也未核实近年所有题目的子任务合分细则。不得拿历史版本填补这些空白。

## 5. Ephyra：研究启动时的访谈快照

> 后续访谈已更新：用户明确选择 IOI 取整份提交最高分、子任务全过才得分，并取消选手侧期望输出功能。以下内容保留为研究启动时的历史快照，不再代表最新待决项；当前需求以 [首版设计访谈](../design/mvp-scope.md) 为准。官方证据不因产品选择而改变。

**访谈已给出的产品意图（不是官方赛事事实）**：需要 ACM、OI、IOI 三种 profile；用户所谓 OI 是最后一次提交、赛中不反馈通过/失败；IOI 有实时分数；OI 与 IOI 均需支持加权子任务；管理员能控制测试点 / 子任务反馈、期望输出和 IOI 实时榜。

**本研究不代替用户决定**：

1. Ephyra 的 IOI 跨提交聚合究竟采用“整份最高”还是“逐子任务最高”；用户尚未明确，不能因名称或实时分数而默认为后者。
2. 子任务内部是否全过得分、取最小比例分或采用其他题面评分，以及分值精度 / 舍入规则。
3. 各 profile 的反馈默认值、适用阶段及受众；“无通过/失败反馈”是否仍显示上传确认、编译错误或样例结果。
4. 期望输出控制针对样例、自测还是隐藏正式测试；实时榜针对选手还是观众，是否延迟 / 封榜。管理员可配置是用户需求，不是上述官方规则的强制要求。
